# 实时示波器采集与界面隔离

## 职责与数据流

| 流程 | 执行位置 | 职责 |
| --- | --- | --- |
| 公共控制 | 顶部公共 BackendClient | 通道配置、启动/停止、设备状态查询，以及其他页面的参数等通信 |
| 数据接收 | 独立数据 BackendClient 与后台采集器 | EA 帧解析、持续取数、原始历史缓存与触发判定 |
| 界面显示 | WPF Dispatcher | 读取一致快照、绘图、测量和交互 |

数据接收不等待公共控制请求，也不依赖界面定时器。后台采集器是独立数据链路的唯一取数者；有积压时立即继续取数，无积压时短暂让出执行。界面只读取历史快照，不消费通信队列。历史容量和原有接收队列上限保持不变，不通过扩容、静默丢点或禁止其他页面操作解决积压。

设备状态查询最多有一个未完成请求；公共链路有普通操作在执行时，暂缓周期查询。查询失败单独显示并在后续恢复，不将控制面的暂时不可用当作健康数据流的故障。收到设备明确停止、设备采样溢出或数据链路/帧异常时仍停止采集。

## 并发与生命周期

采样写入、触发配置和历史复制使用同一个短临界区；所有通道的范围、触发时间和原始点位在一次快照中一致读取。绘图及测量在复制后执行，不持有采集锁。冻结时立即保留独立的原始历史快照，后台继续循环接收；界面暂时繁忙或实时环形历史覆盖旧点时，冻结快照也不被重写。时基调整不清空历史。

停止时取消并等待后台接收器退出，再完成设备停止控制；关闭页面等待接收器、状态查询和控制任务收尾。旧采集会话的状态应答不能影响新的会话。单次捕获完成后的额外输入不追加到已完成的捕获；界面恢复调度后完成停止控制。

## 回归验证

`RealtimeScopeConcurrencyTests` 使用实际 ParameterPanel、两套原生 BackendClient 和独立 TCP 端点；测试端点发送连续计数数据，不使用界面模拟波形源。

- 延迟参数目录应答，同时连续发送 64000 点；公共刷新完成前接收超过原生队列容量的点数。
- 刻意阻塞 WPF 调度，后台仍持续写入超过 32768 个点。
- 公共状态请求失败与恢复期间继续接收，冻结历史保持不变；累计核对 8 通道各 70000 点的值与顺序。
- 设备明确上报采样溢出时仍停止并保留原因。

这些是主机通信与界面并发回归，不替代开发板实测。
