# Perf / Trace / 链表顺序 / J-Link 页面迁移对照

对照 Git 中旧 `ui/perf_tab.py`、`trace_tab.py`、`section_list_tab.py`、`jlink_debug_tab.py` 及相应控制回调实现。旧 Python 文件只用于阅读，没有恢复到工作目录或运行时。四页使用 C# 展示，设备协议、符号解释、Commander 和导出仍由 C++ 后端执行。

## 页面和交互

| 页面 | 旧版入口和行为 | 新实现 |
|---|---|---|
| Perf | 搜索、拉取全部、Task / Interrupt / Code、自动刷新 1s | 上方工具栏；搜索在本地进行，分类拉取保留其他分类缓存；定时请求不重叠，离开页面继续，断开/失败停止 |
| Perf | 更新字典、Reset Peak、协议/单位/时间窗信息 | 第二行；首次分类拉取同步完整字典，字典版本变化时自动重同步一次，复位后重新读取数据 |
| Perf | 四个总负载卡片 | 任务总占用、任务峰值、中断总占用、中断峰值 |
| Perf | Type / Name / Run Time / Max Time / Load / Peak | 左表，逐条接收更新，负载保留三位小数，数值排序、按类型着色、Ctrl+C 复制名称 |
| Perf | 详情和占用率对比 | 右侧显示运行/最大时间、任务周期、当前及峰值占用；Code 不显示不存在的负载 |
| Perf | CSV | 导出全部缓存记录，由后端处理 CSV 转义和文件替换 |
| Trace | 开始/停止上报 | 左侧单按钮，持续采集，确认停止后回到开始状态；切页继续采集 |
| Trace | 行号检索 | 行号高亮，不丢弃或隐藏其他记录，支持十进制及十六进制 |
| Trace | 事件总数、最后时间、最后行号 | 左侧卡片；右侧按接收顺序显示 # / Time (ms) / Line |
| Trace | 主动上报和设备时间单位 | 后端解析控制 ACK 的 unit_us，时间计数回绕扩展；界面增量读取，显示到最新记录 |
| 链表 | MAP 选择、刷新列表 | 顶部；名称解析在后端进行，MAP 与 J-Link 的符号索引互不覆盖 |
| 链表 | 左目录，右顺序/对象名称/地址 | 目录显示名称、节点数、缓存状态；选择只切换视图，刷新所选链表才请求设备 |
| 链表 | 多链表缓存、渐进刷新 | 按链表 ID 缓存，刷新逐步显示；失败保留部分接收节点；连接 epoch 改变时清除旧缓存 |
| 链表 | MAP 重载、单元格复制 | 重载后解析缓存中的原始地址，不需再拉取；Ctrl+C / 右键复制 |
| J-Link | 左侧 Device / Interface / Speed / Connect | Device 可编辑并记忆历史，SWD/JTAG 可选、速率可配置；改变配置后后端重建 Commander 会话 |
| J-Link | ELF/AXF、MAP、Load、Refresh | 文件可分别选择，ELF/DWARF 类型与 MAP 补充符号合并；Refresh 读取当前显示且已展开的标量/指针 |
| J-Link | Expression / Value / Type / Address / Raw / Status | 同一张可展开变量表，名称搜索、分页加载全部根变量和成员，保留类型和数值 |
| J-Link | 结构体、数组、动态指针 | 懒加载成员；指针展开先读当前地址，地址变化清除旧显示子树，空指针标明失败 |
| J-Link | 链表节点展开 | 展开 `next` 等有 DWARF 类型的结构体指针，直接显示下一节点的成员并读取数值；空指针显示结束，指回当前分支的祖先节点标明循环；刷新时地址不变保留展开，地址变化清除旧节点 |
| J-Link | 按地址解析指针目标 | `void*`、字节指针等按当前指向地址精确匹配 ELF 对象，使用该对象的 DWARF 类型展开并读取成员；状态列显示匹配对象名，指向另一种对象时重新解析布局 |
| J-Link | 双击值、Enter 写入，Esc 取消 | 在 Value 单元格内编辑，写入由后端校验并回读；支持 1/2/4/8 字节标量和 FP32/FP64 |
| J-Link | Copy Cell / Row / Expression / Value | 右键菜单和 Ctrl+C；可单独刷新选中的变量 |
| J-Link | 型号识别和文件记忆 | 从所选文件附近的 Keil/J-Link 工程配置读取明确 Device；未找到则保留现有值，不猜测；HC32 使用 Cortex-M4 |

旧版 Target/Dyn 由窗口顶部的地址/Dyn 统一设置，连接时生效。沿用前面已确定的紧凑风格，四页不再额外显示占空间的页面标题和介绍文字；操作反馈保留在底栏。

## 边界

- 尚未对这四页的新交互做 E507 实机验收。自动化回放、模拟 Commander 与 WPF 渲染不等同于实机验证。
- J-Link 写入仍沿用当前 E507 SRAM 范围限制及采集互斥；MMIO、无法解释的 DWARF 位置和位域明确报错。64 位写入使用两个 32 位 Commander 写入并完整回读，不承诺 MCU 观察到原子更新。
- Trace 后端保留最近最多约 10 万条记录，发生历史淘汰时标明数量；开始新一轮前释放上轮数据集，避免重复启动耗尽数据集配额。导出应在重新开始前进行。
- 页面缓存和动态子树属于当前会话；正常退出记忆连接参数、文件路径、搜索和探针设置，不自动连接设备。
- 链表按用户展开逐级读取，不自动遍历整条链。展开深度最多 64 层，每次自动读取最多 256 个直接成员，其余可选中刷新。无目标类型的指针须精确匹配有 DWARF 类型的对象起始地址；仅有 MAP 地址、未匹配地址或多个不同类型的匹配不能推断结构体布局。已有明确结构体指针类型时仍可展开没有全局符号的动态节点。

## 自动化验证

运行 `tests/diagnostic-pages.ps1`：使用 Arm GNU 编译独立 ARM ELF/DWARF 样本，构建 C++ 后端并运行回放测试，然后运行 WPF 自动化。样本不下载到设备。

覆盖分类字典切换、MAP 按地址解析和顺序、CSV 转义与数据集释放、Trace 持续采集与取消、Commander 配置/会话复用、结构体/数组分页、指针及空指针、FP32/FP64 写入回读，以及四页主要控件和缓存交互。界面截图在 `build/ui-verification/`，测试数据不作为实机记录。

2026-09-09 J-Link 专项只读实机验证：使用配置中的 E507 ELF 和 GD32E507ZE 目标，经界面展开按钮将 `section_item_section_shell_FAL_TEST.p_obj` 的地址 `0x20000218` 解析为 `section_shell_FAL_TEST`，显示并读取 9 个成员；同时验证 `p_next` 节点展开。未写入 RAM 或固件。可显式运行 `build/legacy-ui-tests/Frame.UiTests.exe . --jlink-live` 重现；该模式读取当前 `config/native-ui.json` 的 J-Link 设置，截图输出 `build/ui-verification/jlink-live-next.png`，不属于默认回放测试。
