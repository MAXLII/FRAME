# Ethernet 设备发现协议

## 1. 协议用途

Ethernet 设备发现协议用于 FRAME 在当前 IPv4 局域网内搜索提供 FRAME TCP 服务的 GD32E507 设备。

FRAME 在用户选择 Ethernet 或点击“搜索设备”时执行搜索：

1. 枚举电脑上处于启用状态的非回环 IPv4 网卡。
2. 为每个 IPv4 地址创建独立 UDP socket，并绑定该网卡地址和临时源端口。
3. 向每个网卡计算出的广播地址 UDP 5000 端口发送固定发现请求。
4. 在统一的 400 ms 窗口内持续接收设备单播响应。
5. 按 MAC 地址合并经多个网卡或重复请求收到的同一设备响应。

FRAME 在搜索开始时发送一次请求，并在约 150 ms 后重发一次。重发用于降低偶发 UDP 丢包的影响，不延长 400 ms 总搜索窗口。

## 2. 报文约定

- UDP 目标端口：`5000`
- 报文编码：可打印 ASCII，不带结尾 `\0`，不带 CR/LF
- 字段分隔符：`;`
- 键值分隔符：`=`
- 发现报文不封装为 FRAME TCP 字节流帧
- 设备向请求报文的源 IP 和源 UDP 端口单播回复

设备名称和各版本字段不能包含 `;`、控制字符或非 ASCII 字符。

## 3. 发现请求

FRAME 发送的 UDP 数据内容固定为：

```text
FRAME_DISCOVER_V1
```

GD32E507 BSP 只对内容与上述 17 字节完全一致的数据报进行响应。普通 UDP 数据和带有额外前后缀的报文不属于发现请求。

## 4. 发现响应

GD32E507 BSP 回复格式为：

```text
FRAME_DEVICE_V1;name=<设备名称>;ip=<设备IP>;tcp_port=<TCP端口>;mac=<MAC地址>;fw_version=<固件版本>;protocol_version=<协议版本>
```

必需字段如下：

| 字段 | 内容 | 约束 |
| --- | --- | --- |
| `name` | 设备名称 | 非空可打印 ASCII |
| `ip` | 设备当前 IPv4 地址 | 合法点分十进制地址 |
| `tcp_port` | FRAME TCP 服务端口 | 十进制整数，范围 `1 ~ 65535` |
| `mac` | Ethernet MAC 地址 | 六组十六进制字节，以 `:` 或 `-` 分隔；有效单播地址 |
| `fw_version` | 固件版本 | 非空可打印 ASCII |
| `protocol_version` | FRAME 通信协议版本 | 非空可打印 ASCII |

字段顺序按示例发送。FRAME 解析时允许附加未知键值字段，以便协议尾部扩展；必需字段不得缺失、为空或重复。

响应示例：

```text
FRAME_DEVICE_V1;name=GD32E507-PFC;ip=192.168.1.20;tcp_port=9000;mac=02:12:34:56:78:9A;fw_version=1.4.2;protocol_version=1.0
```

## 5. GD32E507 BSP 响应流程

UDP 5000 接收处理执行以下步骤：

1. 按实际 UDP 数据长度检查请求是否与 `FRAME_DISCOVER_V1` 完全一致。
2. 从当前 BSP Ethernet 配置读取设备 IPv4 地址、TCP 服务端口和 MAC 地址。
3. 读取设备名称、固件版本和 FRAME 协议版本。
4. 按第 4 节格式生成 ASCII 响应，确保输出缓冲区容纳完整报文。
5. 向请求的源 IPv4 地址和源 UDP 端口单播发送响应。

发现处理只读取设备身份和连接信息，不改变 IP、TCP 参数或设备运行状态。

## 6. FRAME 严格校验与连接地址

FRAME 只接受满足以下条件的响应：

- 首个字段严格等于 `FRAME_DEVICE_V1`。
- 整个数据报均为可打印 ASCII。
- 六个必需字段全部存在、非空且不重复。
- `ip`、`tcp_port` 和 `mac` 格式及取值有效。
- 每个附加字段都使用 `key=value` 格式，字段名不为空且不重复。

因此，UDP Echo 返回的 `FRAME_DISCOVER_V1`、普通文本和缺少设备字段的数据不会进入设备列表。

响应中的 `ip` 字段用于校验和诊断。FRAME 始终以 UDP 数据包来源 IP 作为列表中的实际 IP 和 TCP 连接地址，避免设备声明地址与实际响应来源不一致时连接到错误地址。FRAME 以规范化后的 MAC 地址作为设备唯一标识，合并来自多网卡和重复请求的响应。

## 7. 搜索结果与重新搜索

搜索结果显示设备状态、设备名称、实际来源 IP、MAC 地址、TCP 端口、固件版本、协议版本和收到响应的本地网卡。

重新搜索时保留已知设备行：本次响应的设备更新信息并标记为在线，未响应本次搜索的设备标记为离线。离线设备不能通过设备列表直接连接，手工 Host 和 TCP Port 连接方式仍然可用。

用户选择在线设备后，FRAME 将来源 IP 和响应中的 TCP 端口写入现有 Host、TCP Port 输入框；双击设备或点击“连接所选设备”使用原有 `EthernetService` 建立 TCP 连接。发现 UDP socket 不进入 `CommunicationManager` 收发队列，不改变 TCP 参数、Scope 或调试通信状态。

## 8. 网络边界

UDP 广播只覆盖当前 IPv4 子网。电脑和设备不在同一子网、VLAN 隔离、主机或设备防火墙阻止 UDP 5000、交换机或无线 AP 过滤广播时，FRAME 可能无法发现设备。

此时可在连接栏手工填写已知 Host 和 TCP Port，直接建立 TCP 连接。
